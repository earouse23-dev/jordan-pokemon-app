- `lib/vision.js` adds one small sealed output schema and conservative normalization. Missing facts remain null; output is `candidate` plus `requiresConfirmation`, without trusted provider mapping, price or authenticity. `api/vision.js` keeps its existing authenticated usage guard; no new provider call was made.
- `app.js` adds bounded JPG/PNG/WebP photo intake (8 MB original, resized JPEG analysis request), stale-response invalidation, uncertain candidate search, fact matching, manual correction, selected USD/EUR form value and retry-key semantics. A selected catalog product can still open its detail preview from the confirmation sheet. Successful save uses existing private attachment upload; a failed attachment upload is reported separately from the already-saved position. Sealed detail now loads owner-scoped attachments on reopen, and multi-unit sealed positions expose the existing sale control.

The previous upsert required UPDATE privilege that the approved schema intentionally does not grant; a real local attachment upload exposed this failure. No table policy or grant was weakened.
- `tests/vision.test.js` and `tests/browser/sealed-collector.spec.js` cover the new mode, image→route→confirmation and guarded real database workflow. The latter checks actual RPC payloads, operation keys, RLS owner isolation, photo metadata, fresh login and EUR/unknown-cost history. Existing 07D browser coverage remains.
