## Applied contract and narrow fixes

Existing observation columns retain native estimate/range/count, canonical printing and grade/qualifier/currency, original evaluation/retrieval/newest-sale dates, rule, provider ID, contributing sale references, truncation and allowlisted normalized source facts. `provider_estimate` + `completed_sale` evidence + `aggregated` derivation still denotes an estimate supported by completed sales, not an individual sale. Generic market indexes remain excluded.

The RPC is SECURITY DEFINER with an empty search path and fully qualified relations. Effective EXECUTE: service_role **yes**, anon/authenticated **no**. Existing observation grants remain authenticated SELECT/DELETE, without INSERT/UPDATE. Service credentials stay in the server/test process. Auth `getUser` verification precedes owner-filtered position lookup; browser owner/amount/sales/validated fields do not produce trusted values.

The RPC locks the authenticated `auth.sessions` row FOR SHARE, checks user/session/expiry, locks the owner-bound saved copy FOR UPDATE, and compares the stored identity/context/status contract again at final persistence. It also checks native/provider/printing/grade fields, producer/type/rule and timestamp/storage invariants. Preflight with no observation happens before local credit reservation and transport. No fallback direct insert exists.

Corrections revealed by validation:

1. Return the actual stored JSONB row, rather than only a UUID. The route revalidates that returned row and responds with its ID, original evaluation/retrieval time and source facts. A duplicate cannot masquerade as a new recorded refresh.
2. Canonicalize equivalent sale order for observation identity; ignore retrieval timestamps in the identity digest and duplicate-equivalence comparison. Preserve the first stored dates. Changed source evidence gets a separate observation, not an overwrite. The frozen estimator is unchanged.
3. After duplicate-ignore insert, compare the existing record's owner/copy/context/data/source facts. Conflicting same-ID rows raise `valuation_observation_conflict`; actual HTTP responses reject them. Native timestamps are compared as typed timestamps, avoiding JSON string-format differences.
4. Retrieval can precede evaluation on a ticking server clock. SQL now requires a nonfuture retrieval not before the newest sale and not after evaluation. The ticking-clock regression failed with HTTP503 under the inverted condition and passed after correction.
5. Stored sold/inactive copies retain historical evidence but no current eligible estimate. Grade/identity/currency changes likewise invalidate current eligibility while preserving original recorded facts.
6. A retained browser regression caught previous-context evidence details surviving a currency-preview change. The shared saved-evidence fallback now requires a matching context key. The unchanged three-browser regression failed before and passed after that small guard.

Creation/grants are wrapped in one transaction. Disable by revoking service EXECUTE; the route stops before reservation/transport. Removal drops only the function and preserves rows/transactions. No broad RPC, RLS or browser grant changes were made.

## Real transactions and deterministic ordering

`tests/graded-valuation-atomic.test-support.js` uses independent container-local psql transactions. Controlled provider-return barriers establish completed changes first. A disposable-only insert trigger/advisory barrier holds the RPC's already-acquired session/copy locks for writer-first checks. `pg_blocking_pids` verifies blocked database work before release; sleeps alone are not evidence. The trigger/function are removed and all transaction processes close.

| Case                                                                         | Actual database outcome                                                                                                                                                                        |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Grade, printing identity, currency or status commits before final validation | HTTP409, no exact observation inserted                                                                                                                                                         |
| Writer obtains locks first, each of those changes queues                     | HTTP200 with original stored context; change proceeds after writer commits; later hydration excludes the current estimate and retains recorded facts                                           |
| Ownership reassignment during delayed response                               | Existing composite owner/transaction FK rejects the transfer (23503); owner remains unchanged and original-owner write is valid. No constraints were weakened to fabricate a transferable copy |
| Completed Auth signout before final validation                               | Session row absent; HTTP401 and no observation                                                                                                                                                 |
| Writer locks session first, independent session deletion queues              | Writer commits its authorized original-session observation, deletion then commits; later request is denied                                                                                     |
| Two identical concurrent HTTP refreshes                                      | One row and one stored evaluation time, matching responses                                                                                                                                     |
| Reordered equivalent evidence; later identical evaluation/retrieval          | Same ID/row/original timestamp, including a ticking-clock retry                                                                                                                                |
| New contributing sale at later evaluation                                    | Separate ID/date and two retained observations; test cleanup removes only its auxiliary synthetic row                                                                                          |
| Existing same-ID data/owner/position/provenance conflict                     | RPC/API rejects, or retained FK prevents the corruption; never false success                                                                                                                   |
| Disable/drop                                                                 | Preflight denies before credits/transport; row count unchanged after function removal; restoration only in disposable stack                                                                    |

Real unauthenticated and second-owner requests reject before provider work. Missing/revoked service EXECUTE, invalid session, another owner's session and expired session reject with no reservation/transport/write. Actual anon/authenticated direct RPC, INSERT and UPDATE attempts are denied by effective grants; second-owner SELECT returns no rows. Insufficient synthetic sales and a synthetic adapter503 produce no observation; adapter failure makes exactly one fake request, with no retry.

Layer responsibilities: server adapter/estimator establishes sale attribution, contributing IDs, amount/range/count and rule; HTTP callers cannot supply those facts. SQL enforces atomic owner/session/context and storage invariants and rejects malformed type/context/native fields and times. The read/response validator reconstructs the estimator from stored facts and rejects mismatched contributing IDs or inconsistent numeric/provenance records. SQL does not duplicate the full estimator. This trust contract assumes the service credential remains private; a public browser grant is not provided.
