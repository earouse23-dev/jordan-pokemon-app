## 2. Exact proposed SQL and data impact

[collector-upgrade.sql](sol-client-07f/collector-upgrade.sql) is a 222 KB review artifact **outside** automatic migrations, SHA-256:

`ee45c20b673437deeab7728ce035530a58fd7eeacbdde063599e00dbba8c6fe6`

It runs nine reviewed sources in one transaction: canonical identity; identity runtime; transparent pricing evidence; reliable ingestion; grading lifecycle; organization/private attachment storage; graded-copy wrappers; sold quantity-zero constraint; and the reviewed 06C service-only RPC. Source file hashes and order are in [the reconciliation artifact](sol-client-07f/object-reconciliation.json). Three narrowly necessary assembly changes are visible in the SQL: flush deferred FK checks with `SET CONSTRAINTS ALL IMMEDIATE` before `ALTER TABLE`; preserve existing public-sequence grants instead of the organization source's blanket revoke; remove the 06C artifact's inner transaction so the outer one is atomic. The full organization migration was necessary because the production `loadPortfolio` selects its columns; an attachment-only slice failed that loader. The grading lifecycle migration was necessary for the same loader's event/status queries.

**Data impact:** canonical identity updates existing identity-bearing rows and enforces non-null canonical IDs; transparent pricing labels/backfills legacy observation metadata; grading lifecycle inserts history events from existing relationships. These are data-writing transformations, even though IDs, original acquisition/sale rows and prices are preserved in the synthetic rehearsal. There is no top-level row deletion or reset in the proposed execution. Some new runtime correction/rollback functions can change or delete scoped data if separately invoked later; 07F did not invoke them. Hosted row cardinality, collision risk, lock duration and restoreability remain untested because hosted user rows were not queried. No hosted execution is authorized by this report.

The SQL is a **single-run** artifact. The first assembled atomic attempt against the earlier disposable project correctly rolled back on PostgreSQL's pending-trigger-events error; adding the deferred-constraint flush resolved it. The final exact hash committed on a fresh owned baseline. Repeating the final script fails at an existing policy and PostgreSQL rolls back the entire attempt; four selected table counts remained `7|10|1|1` before/after. The release operator must not retry blindly or mark migration history applied by name. See [local results](sol-client-07f/local-rehearsal-results.json).
