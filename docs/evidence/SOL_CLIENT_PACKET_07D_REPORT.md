## Subscription proposal for the first public release

No StoreKit, App Store billing entitlement, product IDs, Apple server validation or user billing tables exist in the current app; `web_push_subscriptions` is unrelated push delivery. The smallest compatible design is: add native StoreKit 2 purchase/restore/current-entitlement handling in the existing iOS target, display App Store-returned localized product price/period and renewal facts, associate an Apple verified transaction with the signed-in Supabase owner through a server-verified path, and gate only the client-approved features. A browser-supplied paid flag or a price string must never grant access. Keep existing collection records on expiry/cancellation; any read-only/free access behavior requires Elliott's decision. Use transaction updates and current entitlements for device refresh, and a server status/notification path for cross-session access and refunds/revocation. Apple's [subscription setup](https://developer.apple.com/app-store/subscriptions/) places products in a subscription group; [currentEntitlements](https://developer.apple.com/documentation/storekit/transaction/currententitlements) covers active/grace transactions and excludes revoked/refunded ones; [App Store Server API](https://developer.apple.com/documentation/appstoreserverapi) and [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) govern server status and in-app digital purchases. This is a proposal, **not implemented or activated**.

**One consolidated client decision set:** subscription tier names/number of tiers and exact feature entitlements; price and territories; billing period(s); free trial or other introductory offer; free-access capabilities and existing-user treatment; whether web access shares the same entitlement. Before implementation, separately approve the new native StoreKit integration, any production server-verification dependency and additive entitlement schema, Apple Developer/App Store Connect account/product configuration, and hosted billing/notification endpoints. Later submission requires the actual product metadata, localized terms/renewal price, restore/management path, privacy/support/account-deletion review and sandbox/device checks. No price, feature limit or trial was guessed.
