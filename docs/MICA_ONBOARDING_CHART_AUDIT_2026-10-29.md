# Onboarding and chart audit — 29 October 2026

Scope: repeat the app audit across light/dark appearances and responsive sizes; improve onboarding; repair the portfolio and card-history period controls. This is a software correction, not an App Store submission or authorization to buy services. Ponytail full mode was used; existing authentication, pricing, chart rendering and account-isolation code were reused.

New collectors can go directly to card search. |

| [Notion sign-in guidance](https://www.notion.com/help/log-in-and-out) | Account access and recovery need clear, recognizable routes. | Distinct sign-in/account-creation states, an explicit way back, retained email, and a visible recovery action. New identity providers/passkeys were not added. |

## Findings corrected

1. **Ambiguous account creation.** The old Create account button immediately submitted the sign-in form, with current-password autofill and no separate account-creation presentation. It now switches to an explicit creation state; submission is a separate deliberate action. The email is preserved when switching back.
2. **Duplicate authentication submissions.** Sign-in, signup, reset and confirmation resend now share an in-flight guard, disabled controls and a busy state. Error paths restore controls and keep entered values. Successful authentication/confirmation clears the password field.
3. **Account-existence wording.** Signup now uses one conditional confirmation message rather than a different existing-account message. This corrects Mica's presentation; it does not assert that every upstream timing/HTTP side channel has been eliminated.
4. **Invisible setup block.** Automatic profile completion previously made the app inert behind a hidden dialog. It now displays a short loading state, contains focus, and offers retry on failure. Owner/version checks and interrupted Add/Watch drafts remain preserved.
5. **Empty first visit.** An account with no holdings and no recorded history gets a direct Add your first card action. Historical records for accounts that have owned cards are not replaced by this state.
6. **Fragile timeframe interaction.** The previous native selects were replaced along with their chart markup on selection or background rendering. Programmatic selection worked in the live page, while popup/keyboard interaction did not reliably commit in the controlled background tab. That observation alone cannot prove the exact behavior of a foreground native popup. Both charts now use native, directly clickable period buttons with an explicit pressed state, full accessible names, a 44px minimum target and focus restoration after selection. Existing filtering/rendering is reused and tested by clicks and plotted date bounds, including empty-range recovery.

A longer selected range cannot invent records that a provider has never supplied. All time still means all retained matching records; one year and All time can legitimately contain the same data. Selecting a range does not request new provider prices or rewrite history.

7. **Collection touch target at 759px.** The expanded breakpoint sweep found the More disclosure was 39px wide just below the desktop-navigation breakpoint. Its shared base rule now enforces a 44px minimum width, alongside the existing minimum height. This is corrected in the shared control rather than in a device-specific override.
8. **Narrow card-history header.** The longer period-button group could push the graph down an extra row beside a large exact change amount. The narrow-screen secondary change text uses the existing 12px text floor so the 375px layout retains the graph's placement, without dropping precision or reducing button targets. The original chart-position acceptance limit is retained.
